# Adapted VAYU Architecture

This project uses the VAYU repository as the scientific and visualization foundation while preserving the original AQI/HCHO requirements from `AQI_HCHO_Project_Plan.md`.

## Scientific decisions

| Concern | Adopted implementation | Status and interpretation |
|---|---|---|
| Surface pollution prediction | Random Forest per pollutant, with the existing regression–kriging hybrid available for the demo path | Operational predictor; evaluated with random and spatial cross-validation |
| Official AQI | Deterministic CPCB sub-index engine with the max rule | Primary compliance-facing result |
| Pollution zones | K-Means on scaled AQI plus available HCHO/NO₂/CO and seasonal features | Exploratory segmentation; `k` selected using silhouette score |
| Interpretable HCHO detection | PHV and optional Getis–Ord Gi* | Primary scientific hotspot evidence |
| Planned anomaly baseline | Isolation Forest on HCHO/NO₂/CO and available contextual features | Comparative unsupervised detector, not ground-truth accuracy |
| Hotspot regions | Connected components on the anomaly mask | Produces map-ready regions rather than isolated pixels |
| Source attribution | Existing geography, fire-intensity, EVI, and seasonal rules | Attribution remains a hypothesis requiring validation |
| Presentation | Existing Next.js + MapLibre + deck.gl site, with static JSON layers | Primary polished frontend; Streamlit remains an auxiliary local scaffold |

The project deliberately does **not** replace the interpretable PHV/Gi* detector with Isolation Forest. The two methods answer different questions: PHV/Gi* identifies spatially meaningful HCHO anomalies, while Isolation Forest tests whether a cell is unusual in a multivariate feature space.

## Output contract

All generated web layers live in `public/data/` and are written from precomputed pipeline artifacts. This keeps the demonstration reliable and prevents live GEE requests from being triggered by UI interactions.

### `zone_cells.json`

```json
{
  "method": "KMeans",
  "selected_k": 4,
  "candidate_silhouette": {"3": 0.42, "4": 0.47, "5": 0.39},
  "feature_cols": ["aqi", "hcho", "no2", "co"],
  "cells": [
    {
      "lon": 77.1,
      "lat": 28.65,
      "zone_id": 3,
      "zone_label": "Severe",
      "zone_score": 23.4,
      "aqi": 312.0,
      "hcho": 0.82,
      "no2": 0.64,
      "co": 0.31
    }
  ]
}
```

`zone_id` is ordered by mean AQI from low to high. The labels describe relative cluster severity and should not be presented as official CPCB categories.

### `isolation_hotspots.json`

```json
{
  "method": "IsolationForest",
  "contamination": 0.05,
  "feature_cols": ["hcho", "no2", "co"],
  "n_anomalies": 120,
  "n_clusters": 9,
  "score_definition": "negative sklearn decision_function; larger means more anomalous",
  "cells": [
    {
      "lon": 77.1,
      "lat": 28.65,
      "isolation_score": 0.21,
      "cluster_id": 2,
      "cluster_size": 14,
      "hcho": 0.92,
      "no2": 0.61,
      "co": 0.34
    }
  ]
}
```

The Isolation Forest output is an anomaly ranking. It is not a claim that every flagged cell is a confirmed emission source. The UI must pair it with the PHV/Gi* evidence and the existing attribution caveat.

### `analysis_metadata.json`

This file records the data window, whether the layer is synthetic or real, model settings, validation notes, and the paths used to produce the visible JSON layers. This prevents a real AQI layer from being confused with a synthetic demonstration layer.

## Data-status policy

Every exported layer must declare one of the following statuses:

| Status | Meaning |
|---|---|
| `synthetic_demo` | Generated by `run_demo.py`; useful for reproducible smoke tests and UI development, not real-world evidence |
| `real_observation` | Direct satellite/weather/fire observations, with no surface-AQI model target claim |
| `real_validated_model` | Model output trained and evaluated against station observations, with validation metrics available |

The live site currently has different source windows for some layers. Until a single real-data window is rerun end-to-end, the UI must display the dates explicitly rather than implying a synchronized daily atlas.
